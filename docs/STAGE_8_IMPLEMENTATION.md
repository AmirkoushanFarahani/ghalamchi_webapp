# Stage 8 — Production readiness and hardening

## Scope and baseline

Stage 8 audited the completed Stage 1–7 application without adding a new
product capability or changing its service boundaries. The clean-tree baseline
passed 67 backend/ML tests at 96% coverage, Ruff, strict mypy, 12 frontend
tests, the frontend production build, and Compose config.

## Defects reproduced and fixed

### High severity

- Generic journal reversal could target a journal generated by an invoice or
  payment, allowing the ledger to disagree with the source document. The
  accounting service now rejects direct reversal of source-document journals
  with HTTP 409. A future cancellation/credit-note workflow must update the
  source document and ledger together.

### Medium severity

- Reversing an already reversed journal, or the reversal itself, depended on a
  database failure. Both now have explicit invariants and predictable 409s.
- The dashboard exposed an invoice write action to read-only users. It is now
  guarded by `invoices:write`.
- Raw ML category, segment, explanation, feature, and legacy payment-method
  values could leak English into the Persian UI. They now use Persian labels
  and safe fallbacks; backend validation text is no longer echoed to users.
- Modals now take and contain keyboard focus, support Escape, and restore prior
  focus. Sensitive posting forms use their Persian in-app warning instead of a
  native browser confirmation prompt.
- Mobile tables now retain column context for reports, users, AI history, and
  transaction details.
- Transaction forms now explain missing customer, invoice, account, or open
  period prerequisites in Persian, link to the relevant setup page, and block
  submission until required choices are available.

### Security hardening

- The backend image now runs Alembic, bootstrap, and Uvicorn as the dedicated
  unprivileged `azari` user (UID/GID 999).
- `.env` is ignored and has never been tracked; no private-key file or
  credential-bearing remote URL was found. Audit metadata contains no
  sensitive keys, raw transaction descriptions are absent from ML prediction
  records, required JWT settings remain validated, and CORS remains bounded by
  configured origins.

## Accounting and API verification

A uniquely named development fixture exercised this live API sequence:

```text
customer -> invoice -> issue -> payment -> allocation -> ledger -> reports
```

The invoice reconciled as `250.00 + 25.00 = 275.00`; a full `275.00` payment
reduced balance to `0.00` and status to `PAID`. Both generated journals and the
trial balance were balanced, created revenue was `275.00`, customer
receivables were zero, and party history contained the invoice and payment.
An over-allocation returned 422 without creating a payment. Anonymous access
returned 401 and a VIEWER write returned 403. The fixture was retained in the
local development volume long enough to prove restart persistence and contains
no real customer data.

Regression tests cover unbalanced journals, inactive accounts, closed periods,
duplicate/over allocations, atomic posting failures, immutable posted records,
repeated reversal, and source-document reversal.

## ML verification

All four controlled artifacts were registered and active. Live protected API
calls verified transaction classification, payment risk with model-level
signals, a seven-point cash-flow forecast with ordered intervals, customer
segmentation, history, and append-only feedback. An out-of-vocabulary input
returned confidence `0.2` and `manual_review=true`. There is one active version
for each pipeline and raw transaction descriptions are not persisted.

Artifacts and metrics remain explicitly synthetic. These checks establish
software behavior and cutoff/uncertainty handling, not real-world accuracy,
fairness, or model fitness.

## Remaining limitations and technical debt

- `npm audit --omit=dev` could not reach the npm advisory endpoint because the
  registry connection reset. The lockfile still type-checks, tests, and builds;
  the external advisory check is not claimed as a pass.
- Upstream Starlette/httpx and joblib/NumPy deprecation warnings remain. An old
  Windows ACL also prevents pytest from writing `backend/.pytest_cache`; tests
  pass and Docker excludes that directory.
- Backend source changes invalidate the dependency image layer, making uncached
  rebuilds slower than necessary.
- Supplier payable detail, supplier cash-outflow modeling, user/role mutation
  UI, and real-data ML validation remain documented scope limitations.
- Responsive and keyboard behavior received source, SSR, and live reachability
  checks; the repository has no full browser automation suite.
